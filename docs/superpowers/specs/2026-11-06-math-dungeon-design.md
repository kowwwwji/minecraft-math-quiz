# 算数ダンジョン（Minecraft Java 版データパック）設計書

作成日: 2026-11-06（2026-11-07 改訂: 命 3 つと TNT、ボタンの見た目、花火の出し方。2026-11-21 改訂: 3 つの数の式と 2 年生向け難易度）

## 目的と背景

小学 1〜2 年生の子どもが Minecraft の中で算数の問題を解きながら進む「ダンジョン」を作る。
看板に問題が出て、ボタンで答えを選ぶ。正解なら次の部屋への扉が開き、不正解なら足元の床が
抜けて落とし穴に落ちる。落ちても痛くなく、すぐ戻ってやり直せる。

親（依頼者）がコマンドを 1〜2 回打つだけで遊び始められ、問題は毎回ランダムに出るので
何度でも遊べることを狙う。

2 つの数の足し算・引き算は 1 年生の子どもがすぐ答えてしまい手応えがなくなったため、1 年生向けは 3 つの数の式にし、2 年生向け（2 桁の足し算・引き算、九九）を加える。

## ゴール

- 毎回ランダムな問題が出る（同じ問題の繰り返しにならない）。
- 「正解 → 扉が開く」「不正解 → 落とし穴」が一目で分かる。
- 落ちても安全で、子どもが一人で部屋に戻れる。
- 命は 3 つ。3 回目の不正解で TNT が爆発して子どもは死に、遊びは終わる（緊張感のため）。
- 難易度（学年 × 3 段階）を親が簡単に変えられる。
- データパック 1 つで完結し、ワールドにコピーしてコマンドを打てば動く。

## やらないこと（non-goals）

- マルチプレイ、サーバー対応。
- 統合版（Bedrock）対応。
- Mod / リソースパック。見た目はバニラのブロックとテキストだけで作る。
- 問題の成績記録や採点履歴。
- 3 桁以上の数、割り算、筆算の表示、九九の範囲を超えるかけ算。
- 繰り上がり・繰り下がりを狙って出す（2 桁の数をランダムに選んだ結果として混ざるだけ）。

## 失敗とみなすこと（anti-goals）

- 3 回目の不正解以外で子どもがダメージを受ける、死ぬ、閉じ込められて出られなくなる。
- 3 回目の爆発で部屋が壊れ、次に遊ぶとき `setup` の建て直しが要る。
- 問題や選択肢の文字が小さくて読めない。
- 不正解のあと同じ問題がそのまま残り、消去法で正解できてしまう。
- 親がコマンドブロックを手で置いたり座標を調整したりしないと動かない。

## 前提・制約

| 項目 | 値 |
|------|----|
| Minecraft | Java 版 26.3（データパック形式 `121`） |
| ワールド | `~/Library/Application Support/minecraft/saves/さんすう/`（シングル・コマンド許可済み） |
| 生成ツール | Python 3.11（mise 管理）。外部ライブラリなし |
| 文字 | 問題は数字と記号（`3 + 4 + 2 = ?`、`7 × 8 = ?`）。メッセージ（せいかい！等）はひらがな |

Minecraft 26.3 は執筆者の知識より新しい。コマンド構文（特に `text_display` の
NBT、看板のテキスト、`random`、マクロ関数）は minecraft.wiki の 26.3 の記述と
ゲーム内テストで必ず確認する。26.1 で `/time query daytime` が
`/time query minecraft:day` になるなどの変更があったが、本設計で使う
`fill` `setblock` `execute` `scoreboard` `random` `tellraw` `title` `tp` `gamemode`
`playsound` `summon` `data` `function` は基本構文に変更がない想定で書く。

## 遊び方（親の操作）

1. データパックを `saves/さんすう/datapacks/mathquiz/` にコピーする（付属の `install.sh`）。
2. ワールドを開き `/reload`。
3. `/function mathquiz:setup` でダンジョンを建てる（一度だけ。再実行で建て直し）。
4. `/function mathquiz:start` で子どもを 1 部屋目に送り、問題を出す。
5. 遊び終わったら `/function mathquiz:quit` でクリエイティブに戻し、`setup` を打った場所へ移動する。
   3 回目の不正解で死んだときも同じ場所にリスポーンし、自動でクリエイティブに戻る（遊びは終わり。続けるなら `start`）。

難易度は次の関数で切り替える（`start` の前後どちらでもよい。次に出る問題から反映）。
名前は「学年_段階」。2 年生は段階が上がると九九が混ざる。

| 関数 | 内容 | 答えの範囲 |
|------|------|-----------|
| `/function mathquiz:level/g1_easy` | 3 つの数の足し算だけ（`2 + 3 + 1`） | 0〜10 |
| `/function mathquiz:level/g1_normal` | 3 つの数の足し算・引き算混じり（`5 + 3 - 2`、`9 - 2 - 3`）。既定 | 0〜10 |
| `/function mathquiz:level/g1_hard` | 同上 | 0〜20 |
| `/function mathquiz:level/g2_easy` | 2 桁の足し算・引き算（2 つの数。`47 + 28`、`63 - 19`） | 0〜99 |
| `/function mathquiz:level/g2_normal` | 2 桁の足し算・引き算と九九（`7 × 8`）を半々で出す | 0〜99 |
| `/function mathquiz:level/g2_hard` | 2 桁の 3 つの数の足し算・引き算（`23 + 45 - 18`）と九九を半々で出す | 0〜99 |

2 年生の上限が 99 なのは、式・途中の計算・答え・選択肢のどこにも 3 桁の数を出さないため（non-goals）。

## 子どもの体験（一部屋の流れ）

1. 部屋に入ると、正面の壁の上に大きな文字で問題が浮かんでいる（例 `3 + 4 + 2 = ?`）。
2. 正面の壁に 3 つのボタンが横に並び、各ボタンの上に答えの候補が大きく表示されている。
   ボタンは石レンガの壁に溶け込まないよう木のボタンにし、ボタンの裏の壁 1 ブロックを赤・黄・青の色付きブロックにする
   （「3 つの色付きの的」として見える）。
3. 正解のボタンを押す
   - 「せいかい！」が画面中央に出て、レベルアップの音が鳴る。
   - 部屋の横の鉄格子の扉が消えて、次の部屋へ進める。
   - この部屋のボタンは以後押しても何も起きない。
4. 不正解のボタンを押す（1 回目・2 回目）
   - 「ざんねん…」と残りの回数（「あと 2 かい」）が画面中央に出て、低い音が鳴る。
   - ボタン壁の前の床（壁から 5 ブロック分、部屋の幅いっぱい）が消えて、下の穴に落ちる。穴の底は水で、ダメージはない。
     ボタンは 4 ブロックほど離れても押せるので、届く範囲すべてを落とし穴にして「押したら必ず落ちる」ようにする。
   - 穴の端にはしごがあり、登ると部屋の入口側の角から部屋に戻れる。
   - 3 秒後に床が元に戻り、**新しい問題**が同じ部屋に出る。
5. 不正解のボタンを押す（3 回目。回数はダンジョン全体の通算で、`start` で 0 に戻る）
   - 「ばくはつ！」が出て、足元に TNT が現れ、点滅して 2 秒後に爆発音と煙とともに子どもが死ぬ。
   - 部屋は壊れない（TNT は威力 0 で出し、子どもへのダメージは `damage` で与える）。
   - リスポーン地点は爆発の前に `setup` を打った場所にしておく。リスポーンしたら自動でクリエイティブに戻り、
     「もういちど あそぶなら /function mathquiz:start」と出る。
   - 死んでも持ち物が散らばらないよう `setup` で `keepInventory` を有効にする（専用ワールドなので構わない。作る側の判断）。
6. 5 部屋目をクリアすると扉が開く。ゴール部屋に**入った瞬間**に「ゴール！」の表示と音、屋根の上から花火が上がる
   （3 発ずつ 3 回。回数は設定で変えられる）。中にはダイヤやケーキ入りの宝箱。
   ゴール部屋の天井はガラスで、花火は屋根の上で爆発するため子どもにダメージは入らない。
   ゴール部屋の明かりは天井の代わりに床を光るブロックにする。

子どもは `start` 時にアドベンチャーモードになる（ブロックを壊して抜け出せない。ボタンは押せる）。

## 構造（ダンジョンの形）

- 地形に依存しないよう、空中の **y=120** に石レンガで床・壁・天井を持つ閉じた建物を建てる。
  `setup` は先に該当範囲を空気で埋めてから建てる。
- 原点は **x=0, z=0**（`build.py` の設定で変えられる）。「さんすう」は専用の新規ワールドで守るものが
  ないため、スポーン付近の地形と重なっても構わない。`setup` は最初にプレイヤーを原点へ `tp` して
  チャンクを読み込ませてから建てる（`forceload` は使わない）。これは執筆者の判断。
- 部屋は **+X 方向に一直線**に 5 部屋 + ゴール部屋。各部屋の内寸は幅 9（Z）× 奥行 7（X）× 高さ 5。
- 部屋の配置（上から見た図。右が +X）

```
 入口 → [部屋1] 扉 [部屋2] 扉 [部屋3] 扉 [部屋4] 扉 [部屋5] 扉 [ゴール]
```

- 各部屋の中（上から見た図。上が +Z、右が +X = 進行方向）

```
  Z
  ^   ┌─────────────────┐
  |   │ L               │   L : はしごの縦穴（1×1、常に開いている）
  |   │                 │
  |   │   [ボタン壁]     │   ボタン壁: 部屋の奥(+X)ではなく +Z 側の壁に
  |   │ ■ ■ B1■ B2■ B3■ │       3 つのボタン。上に答えの候補、さらに上に問題文
  |   │ ■ ■ ■ ■ ■ ■ ■ ■ │   ■ : 落とし穴になる床。ボタン壁から 5 ブロック分、部屋の幅いっぱい
  |   │ ■ ■ ■ ■ ■ ■ ■ ■ │       （ボタンが届く範囲を全部覆う。L の縦穴の列は除く）
  |   │ ■ ■ ■ ■ ■ ■ ■ ■ │
  |   │ ■ ■ ■ ■ ■ ■ ■ ■ │
  | ──┤入               扉├──   入: 前の部屋からの入口 / 扉: 鉄格子 2×2、正解で消える
  |   │                 │   入口と扉は -Z 側の残り 2 ブロック幅の通路でつながる
  |   └─────────────────┘
  +-------------------------> X
```

- 落とし穴は床の下 6 ブロックの縦穴。底 2 段は水。穴の底とはしご縦穴の底はつながっている。
- 床を戻すとき、まだ穴の中に子どもがいても埋めてはいけない（床の高さにいる場合は穴の底へ `tp` してから戻す等）。
- 問題文・答えの候補は `text_display` エンティティで表示する（大きく拡大でき、遠くからでも読める）。
  看板は使わない（文字が小さいため）。これは執筆者の判断。
- 光源は天井にシーライトやグロウストーンを埋め込み、常に明るくする（ゴール部屋だけは天井がガラスなので床を光源にする）。
- 花火は `summon` した花火ロケットで出す。花火は爆発点から 5 ブロック以内の生物にダメージを与えるので、
  子どもと同じ部屋では打ち上げない。屋根の上（ガラス越し）で上げる。

## 出題ロジック

- 1 部屋の問題は「その部屋が有効になった時」（start 時の 1 部屋目、前の部屋の正解時、落とし穴後の復帰時）に生成する。
- 難易度は次の 5 つの値で表す。問題の種類ごとに関数を分けず、同じ生成手順をこの値で振り分ける。

  | 値 | 意味 | g1_easy | g1_normal | g1_hard | g2_easy | g2_normal | g2_hard |
  |----|------|---------|-----------|---------|---------|-----------|---------|
  | 上限 | 式に出る数・途中の計算・答え・選択肢の上限 | 10 | 10 | 20 | 99 | 99 | 99 |
  | 下限 | 式に出る数の下限（2 桁なら 10） | 1 | 1 | 1 | 10 | 10 | 10 |
  | 項数 | 足し算・引き算の式に出る数の個数 | 3 | 3 | 3 | 2 | 2 | 3 |
  | 引き算 | 引き算を混ぜるか | なし | あり | あり | あり | あり | あり |
  | 九九 | 九九を 1/2 の確率で混ぜるか | なし | なし | なし | なし | あり | あり |

- 足し算・引き算の式: 左から順に数と記号を決めていく。`a` は下限〜上限から選び、以降の数は
  「`+` なら上限を超えない範囲」「`-` なら途中の計算が 0 未満にならない範囲」で下限以上から選ぶ。
  `+` と `-` は 1/2 で選ぶが、片方しか選べないとき（残りが下限未満、途中の値が下限未満）はもう片方にする。
  引き算なしの難易度では、後ろの数のぶん（下限 × 残り項数）を先に取り置いて `+` が必ず選べるようにする。
  これにより式に出る数はすべて下限以上（0 は出ない）、途中の計算も答えも 0〜上限に収まる。
- 九九: `a × b = ?`。`a` `b` は 1〜9。
- 選択肢は 3 つ。正解 1 つと誤答 2 つ。誤答同士・正解と重複せず、0〜上限に収まる。3 つの並び順はランダム。
  - 足し算・引き算: 正解 ±3 の範囲で 0〜上限に収まる値（正解を除く）から、重複しないよう 2 つ選ぶ。
    上限は 10 以上なので候補は常に 3 つ以上ある。
  - 九九: 正解 ±1〜3 は九九の表にない数ですぐ見抜かれるため、`(a ± 1) × b` と `a × (b ± 1)` を誤答にする
    （掛ける数が 1〜9 を外れる向きは逆にする。`a = b` で 2 つが同じ値になったら後者を `a × (b ± 2)` にする）。
- 乱数は `random value` コマンドを使い、結果をスコアボードに入れて計算する。

## 状態の持ち方

- スコアボード objective `mq` を 1 つ使い、ダミープレイヤー名で値を持つ
  （例 `#room` 現在の部屋番号、`#a` `#b` `#c` `#op1` `#op2` `#ans` `#c1` `#c2` `#c3`、
  難易度の 5 つの値 `#max` `#lo` `#terms` `#sub` `#mul`、`#lock` 入力受付中か）。
- 難易度の既定値は `load` で「未設定なら `g1_normal`」として入れる。未設定の判定には、この改訂で新しく
  増えた値（`#terms`）を使う。古い版で遊んだワールドには `#max` だけが残っていて、`#max` で判定すると
  新しい値が入らないまま出題が壊れるため。
- 一度に有効な部屋は 1 つだけなので、問題の状態は部屋ごとではなく「現在の部屋」1 組だけ持つ。
- ボタン検出は `tick` 関数で「現在の部屋」の 3 つのボタンの `powered=true` を毎ティック見る。
  押下を 1 回だけ処理するため、処理した直後に `#lock` を立て、床復帰または扉開放の処理が終わるまで再入力を無視する。
- 時間差の処理（3 秒後に床を戻す、TNT の爆発）は `schedule function ... Nt` を使う。
- 不正解の回数は `#miss` に持ち、`start` で 0 にする。
- 死亡の検出は `deathCount` 基準の objective で行い、リスポーン後に `tick` で拾ってクリエイティブに戻す。
- 「ゴール部屋に入った」は `tick` で「現在の部屋がゴール部屋」かつ「プレイヤーがゴール部屋の内側にいる」で検出し、1 回だけ処理する。

## 生成の仕方（作る側の構成）

- リポジトリ: `~/ghq/github.com/kowwwwji/minecraft-math-quiz`
- `build.py`: 設定（原点座標・部屋数・部屋サイズ・ボタン位置など）から `dist/mathquiz/` に
  データパック一式（`pack.mcmeta`、`data/mathquiz/function/*.mcfunction`、`data/minecraft/tags/function/{load,tick}.json`）を書き出す。
  座標計算をすべて Python 側で済ませ、mcfunction には絶対座標を書く。マクロ関数は使わなくてよい。
- `install.sh`: `dist/mathquiz/` をワールドの `datapacks/` へコピーする。コピー先はスクリプト冒頭の変数で変えられる。
- 外部ライブラリは使わない。テストは `python3 -m unittest`（出題ロジックの境界、座標計算、生成されるファイルの存在）。
- ゲーム内の動作確認は親（依頼者）が行う。確認手順（`/reload` → `setup` → `start` → 正解・不正解を 1 回ずつ）を README に書く。

## 作る側に任せること

- 部屋の内装・ブロックの種類（石レンガが基本であれば自由）。
- `text_display` の大きさ・色・背景。読みやすさを優先する。3 つの数や 2 桁の式は幅が広がるので、最長の式（`23 + 45 - 18 = ?`）がボタン壁の幅（7 ブロック）に収まる拡大率にする。
- 音と演出の具体的な選択（`playsound` の種類、花火の色など）。
- `tick` 関数でのボタン検出を、より軽い方法（`execute if block` 以外）に置き換えてよい。
- 落とし穴の深さ・水の量は「ダメージが出ない」範囲で調整してよい。
- 色付きブロックの種類・木のボタンの種類、TNT の演出（煙・音）、花火の回数と色。
